Task A (Piet Mondrian) and Task C (physics simulation on the GPU), one file, plain JavaScript + WebGL2, no libraries.

A - Piet Mondrian, three ways

One composition, stored as plain data (rectangles + colours). The same rect(st, pos, size) idea is evaluated three times: by a GLSL fragment shader on the GPU, by the identical algorithm in JavaScript on the CPU (per pixel), and by CSS grid. Sliders affect the first two.

C - Gray-Scott reaction-diffusion on the GPU

Two chemicals A and B live in the RG channels of a float texture. A fragment shader computes one time step per pixel, the result goes into a second texture, then the two swap (ping-pong). JavaScript only drives the loop, mouse and uniforms. Enhancements over the textbook version: parameter map, walls (absorbing or reflecting), anisotropic diffusion, relief rendering.

Bonus - the same simulation on CPU workers and on the GPU

Identical Gray-Scott step, identical start state. The CPU version splits the grid into horizontal strips, one Web Worker per strip. Each worker gets its strip plus a halo of 10 rows on both sides and runs 10 steps before the strips are stitched back together (the halo shrinks by one valid row per step, so the core stays exact). The GPU runs the pixel shader.

  • Bars use a log scale, otherwise the CPU rows would be invisible next to the GPU.
  • Workers cannot share memory here: SharedArrayBuffer needs cross-origin isolation, which a double-clicked file:// page does not have. So data is copied each round, and that copy is part of the CPU time.
  • The GPU time includes a 1-pixel readPixels at the end, which forces the queued work to finish; without it the timer would only measure command submission.
