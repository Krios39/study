Deliverable Question: How and why NumPy speeds up array operations

Question: How and why does the NumPy library speed up array operations compared to Python lists?

NumPy achieves substantial speedups over standard Python lists due to architectural and memory-level differences:

  • Contiguous Memory Layout: A Python list stores pointers to arbitrary objects scattered across memory (pointer indirection), resulting in frequent CPU cache misses. NumPy's ndarray allocates a continuous block of memory for homogeneous data types (e.g., 64-bit floats), maximizing CPU cache locality and spatial prefetching.
  • Compiled C/Fortran Implementations: Array iterations and calculations in NumPy run entirely inside optimized low-level routines (compiled C/Fortran) rather than through the Python bytecode virtual machine loop.
  • Elimination of Type Checking Overhead: Python lists check types dynamically on every access and arithmetic operation. NumPy arrays are statically typed, skipping runtime dispatching.
  • SIMD Vectorization & Multi-Threading: NumPy leverages hardware-level SIMD instructions (AVX, SSE) and links against multithreaded BLAS/LAPACK libraries (such as OpenBLAS, MKL), performing vector and matrix operations across multiple CPU cores simultaneously.

Question: Which one is faster? Can we make it run faster?

Answer: The iterative algorithm is exponentially faster. The recursive method duplicates subproblems, scaling at O(phi^n) ~ O(1.618^n), requiring over 7 million calls at n = 32. The iterative version operates in linear time O(n). We can achieve even faster sublinear runtime O(log n) using matrix exponentiation via repeated squaring.
