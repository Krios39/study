T2. Maximum path sum: local return versus global answer

Algorithm Implementation & Sign Transformation:

To create mixed-sign trees, the original Collatz trees were duplicated, preserving their exact structural parent-child links. A breadth-first search (BFS) traversal was applied, and every third node visited had its value multiplied by -1. Nodes were neither reinserted nor reordered.

Consequently, these modified structures immediately violate the core Binary Search Tree (BST) invariant. In a valid BST, every node in the left subtree must be strictly less than its parent, and every node in the right subtree must be strictly greater. Negating arbitrary nodes breaks this strict monotonic ordering. For instance, a positive right child negated into a negative value becomes smaller than its parent, invalidating the search property. Therefore, they are now ordinary binary trees utilized solely for structural path-sum evaluation.

The answers (Independent Reasoning):

  • Best one-ended path (Local Return to Parent): A recursive call must return the maximum path extending strictly downward through only one of its children (or just itself if children yield negative sums). It cannot return a branching path, because the parent node can only connect to one continuous line without violating the non-repeating node constraint.
  • Best complete path (Global Answer for the Tree): Simultaneously, the algorithm evaluates if the current node acts as the peak of an "arch" connecting its left and right subtrees. This complete path sum (left_branch + node + right_branch) is functionally closed and cannot be extended upward. If this local arch exceeds the historically recorded maximum, it updates a global variable maintained across the entire tree traversal.
  • Exhaustive Validation Result: The O(N) recursive algorithm's outputs match the deliberately slow $O(V!)$ brute-force method perfectly across all small hand-built trees, confirming that dropping negative branches and globally recording isolated arches accurately captures the maximum possible sum in non-BST structures.

The answers:

  • Why the AVL condition keeps search depth logarithmic:
    The AVL condition strictly mandates that for any given node, the height difference between its left and right subtrees (the balance factor) never exceeds 1. This mathematical invariant actively prevents the tree from degrading into a skewed linear chain, which naturally occurs in ordinary BSTs during monotonic insertions. By triggering corrective rotations (LL, RR, LR, RL) the moment this threshold is breached, the AVL tree aggressively redistributes nodes. This structural guarantee forces the tree to remain highly packed, mathematically bounding the maximum tree height to strictly $O(\log N)$.

T5. How much can local order damage an unbalanced BST?

1. Experimental Setup & Predictions:

  • Generator & Seeds: Blocks of length $L$ were concatenated and shuffled using Rust's rand::rngs::StdRng. Five fixed seeds were used across all tests: [42, 123, 777, 2026, 9999].
  • Correctness Checks: Iterative search confirmed the BST invariant, and iterative inorder traversal successfully returned exactly 0, ..., n-1 for every constructed tree without encountering stack overflow.
  • Counting Convention Verification: By defining the root depth as 0, our counting perfectly aligns with the algorithm's mechanics. When inserting a node at depth $D$, it passes through exactly $D$ ancestors (making $D$ comparisons). A successful search for it makes the exact same $D$ comparisons to traverse the ancestors, plus $1$ final comparison to match the target itself. Thus, insert_comparisons = depth, and search_comparisons = depth + 1.
  • Independent Prediction: I predict that as the block length $L$ increases, the tree's quality will severely degrade. Because each block of length $L$ is internally sorted, inserting it will create a straight linear chain leaning to the right. Consequently, the tree's height will skyrocket, shifting both construction and search costs from logarithmic $O(\log n)$ efficiency towards linear $O(n)$ behavior.

  • Why short increasing runs change the tree shape and cost:
    Even small sorted blocks (like $L=4$) force the BST to create localized right-leaning linear chains. Instead of distributing nodes evenly across left and right branches (which logically splits the search space in half), the algorithm sequentially attaches each node as the right child of the previous one within that block.
