The sequences were then sequentially inserted into initially empty, unbalanced Binary Search Trees (BST). Duplicate values were strictly ignored during insertion, and the trees were deliberately kept unbalanced with no rotational optimizations applied.

The answers:

  • BST Invariant Verification: The invariant dictates that for any given node, all elements located in its left sub-tree must be strictly smaller, and all elements in its right sub-tree must be strictly greater. To ensure structural integrity, an automated recursive validation function check_invariant() was executed after every single insertion operation, successfully asserting that no violations occurred across all four trees.
  • Special Property of In-order Traversal: An in-order traversal (Left → Root → Right) executed on a valid Binary Search Tree inherently outputs the contained elements in a strictly monotonically increasing (sorted) order. This occurs as a direct mathematical consequence of the BST invariant: the algorithm exhausts all smaller values by recursively drilling down the left branches, outputs the current median/root value, and then processes the strictly greater values residing in the right branches.
  • Comparison of the Large Tree: The tree generated from 77031 acts as a stark demonstration of unbalanced BST degradation. While small trees maintained reasonable heights ($h \le 9$), the large sequence produced a highly skewed structure with a height of $27$ and a node count of $351$. The depth distribution reveals a heavily bloated mid-section (maximum width of $35$ at depth 7), highlighting that without rebalancing mechanisms (like AVL rotations), structural operations trend toward worst-case linear time.
T2. Maximum path sum: local return versus global answer

Algorithm Implementation & Sign Transformation:

To create mixed-sign trees, the original Collatz trees were duplicated, preserving their exact structural parent-child links. A breadth-first search (BFS) traversal was applied, and every third node visited had its value multiplied by -1. Nodes were neither reinserted nor reordered.

Consequently, these modified structures immediately violate the core Binary Search Tree (BST) invariant. In a valid BST, every node in the left subtree must be strictly less than its parent, and every node in the right subtree must be strictly greater. Negating arbitrary nodes breaks this strict monotonic ordering. For instance, a positive right child negated into a negative value becomes smaller than its parent, invalidating the search property. Therefore, they are now ordinary binary trees utilized solely for structural path-sum evaluation.

The answers (Independent Reasoning):

  • Best one-ended path (Local Return to Parent): A recursive call must return the maximum path extending strictly downward through only one of its children (or just itself if children yield negative sums). It cannot return a branching path, because the parent node can only connect to one continuous line without violating the non-repeating node constraint.
  • Best complete path (Global Answer for the Tree): Simultaneously, the algorithm evaluates if the current node acts as the peak of an "arch" connecting its left and right subtrees. This complete path sum (left_branch + node + right_branch) is functionally closed and cannot be extended upward. If this local arch exceeds the historically recorded maximum, it updates a global variable maintained across the entire tree traversal.
  • Exhaustive Validation Result: The O(N) recursive algorithm's outputs match the deliberately slow $O(V!)$ brute-force method perfectly across all small hand-built trees, confirming that dropping negative branches and globally recording isolated arches accurately captures the maximum possible sum in non-BST structures.
