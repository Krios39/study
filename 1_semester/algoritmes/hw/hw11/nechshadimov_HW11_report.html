Task T1: Build the edit-distance matrix

Method

  • Table: DIST[i, j] is the cheapest way to turn the first i letters of causality into the first j letters of casualty. Row 0 and column 0 are the empty prefixes (j insertions, i deletions), as in the starter.
  • Recurrence (unit costs): the table is a grid graph whose edges only go down, right or diagonally, so the shortest path to a cell is the best of its three predecessors: 
    DIST[i, j] = min( DIST[i−1, j]   + 1,                                delete source[i]
                  DIST[i, j−1]   + 1,                                insert target[j]
                  DIST[i−1, j−1] + (0 if source[i] = target[j] else 1) )   keep / substitute
    The table is filled row by row, so all three predecessors are already known. The distance is DIST[9, 8].
  • Traceback: from the bottom-right cell, step back to a predecessor whose value plus the step cost gives the current value (preference: diagonal, then deletion, then insertion). Each step is one edit. The edits are then applied to causality in forward order, and the script checks that the result is casualty and that the costs add up to the distance.
  • Changed rule: A, adjacent swap at cost 1. A fourth edge from DIST[i−2, j−2] with cost 1, allowed when source[i−1..i] equals target[j−1..j] reversed. All other costs are unchanged.
  • Prediction (before recomputing): the words differ by the swapped pair us/su and one extra i. With unit costs the swap needs two edits, with rule A one, so the distance should drop from 3 to 2, and only cells from the swapped pair on should change.

Discussion

  • The prediction holds: the distance drops from 3 to 2. The changed cell is DIST[caus, casu]: with unit costs it is 2 (two substitutions u→s, s→u after the common ca), with rule A it is DIST[ca, ca] + 1 = 1 through the swap edge.
  • The saving propagates: the cells after the swapped pair on the path are 1 lower, while the cells before it are identical in both tables. The rest of the path (keep al, delete i, keep ty) is the same.
  • The unit-cost traceback is not the only optimal one; e.g. deleting u and inserting it after s also costs 2 for the pair. The script picks one path by the fixed preference order.
Task T2: Compare three models

Method

  • Queries: rows 0, 10, …, 90 of levels 1, 3 and 6 (30 queries), each compared with all 100 originals. search returns all words with the minimum cost; the notebook's outcome and evaluate count the three outcomes.
  • One distance function distance(source, target, model) (in words.py, using the DP of edit.py) with the same recurrence as T1; only the substitution cost and the optional swap edge depend on the model. Costs are integers internally (1 = 5 units, 0.2 = 1 unit), so ties are exact.
  • Model 1, unit: insert, delete, substitute 1; equal letters 0.
  • Model 2, weighted: insert and delete 1; substitution 0.2 if the letters differ only in case (a↔A) or form a similar pair, otherwise 1. Similar pairs (chosen after looking at the corruptions in the data): a↔ä, e↔ë, o↔ö, u↔ü and l↔i. They are compared after lower-casing, so a case change inside a pair is also cheap (Ä↔a, L↔i, I↔l all cost 0.2).
  • Model 3, weighted + swap: model 2 plus a swap of two adjacent letters. A strict swap (letters must be exactly equal) did not change a single test score, because from level 3 on the swapped letters are usually also re-cased (…riDS… for …rdis…). I therefore use a soft swap: allowed when each swapped letter matches up to case or a similar pair, cost 1 plus 0.2 for each such letter. The strict version is kept as an extra row for comparison.
  • Checks: the T1 values (3 with unit costs, 2 with the swap), empty words (cost = length), a case-only change, a similar-letter substitution (also with case) and a swap give the expected costs.

Discussion

  • Example where the model changes the winner: RecombiatRioilTY (level 6, row 30). With unit costs every capital letter is a full substitution, and recombinationally (cost 7) beats the original recombinatoriality (cost 9): a miss. With the weighted model the four capitals cost 0.2 each and the l/i confusion 0.2, so the original costs 4.2 and wins uniquely. At level 3 the same row gives a unit-cost tie between recombinatorial and recombinatoriality, which the weighted model also resolves.
  • Example where the swap changes the score: LniaxriDShipltnäRy → interdisciplinary (level 6, row 0) costs 7.8 with model 2 and 7.0 with the soft swap: the two substitutions i→d, D→i (1 + 1) become one swap iD→di (1 + 0.2). The strict swap does not apply here because of the capital D, so it stays at 7.8.
  • The weighted model is enough for these queries: it finds all 30 originals uniquely, so the swap cannot improve the counts. Case changes and look-alike letters are the dominant corruption from level 3 on; they make unit-cost scores grow fast (e.g. 10 for IniaxriDShipltnaRy), while the weighted model treats them as minor. Swaps are rarer, and on the 30 test words they only lower the cost of the word that already wins.
  • The weighted model is designed for exactly these corruptions. On other data (e.g. real misspellings) the cheap l/i pair could also make wrong words cheaper; with 100 long and dissimilar words this does not happen here.
Task T3: Find the five best matches in a longer text

Method

  • Query interdisciplinary (original row 0); text: all words of levels 1–6 joined without separators (10,446 characters).
  • Semi-global DP (match.py): the same table with the query letters as rows and the text letters as columns, with two changes. The first row is all zeros, so the path may start in any column (text before the match is free). The answer is the minimum of the last row, so the path may end in any column (text after the match is free). The first column still counts deletions of query letters, so the whole query must be aligned.
  • Start of the match: each cell stores the column where its path left row 0, copied from the chosen predecessor. The function returns (cost, start, end), zero-based and end-exclusive.
  • Ties and nonempty matches: among equal predecessors the order is diagonal, insertion, deletion; among equal end cells the leftmost wins. Ends whose path consumed no text (start = end) are skipped. Checks: best_match("cat", "xxcutyy") == (1, 2, 5) and best_match("a", "b") == (1, 0, 1).
  • The notebook's top_five calls this function on the unreported parts of the text. The cost of every returned substring was recomputed with the T2 distance function and agrees.
  • Optional: the same matcher with the weighted + soft swap model from T2.

Task T4: One query against 100 rows

Method

  • Data: the supplied HW11_pyramid_A.png and HW11_pyramid_B.png (100 × 150, loaded and hash-checked by the notebook's load_pair, not resized). Query: row 55 of A. Candidates: all 100 rows of B.
  • Pointwise score: Σ (query[x] − row[x])² over the 150 columns.
  • DTW (dtw.py), global with squared local cost: 
    D[0, 0] = 0,   D[i, 0] = D[0, j] = ∞
D[i, j] = (query[i] − row[j])² + min(D[i−1, j], D[i, j−1], D[i−1, j−1])
    score = D[150, 150]. Steps (1,0), (0,1), (1,1). The local cost is paid for every cell on the path, so stretching is paid by matching the same sample several times.
  • Ranking: the lowest score wins, ties go to the smaller row. Only after ranking, the known transformation (shift by 8 rows) gives the true counterpart, row 63, for the evaluation.

Discussion

  • Pointwise fails: it picks row 11 (plain sky) and ranks the true row only 21st. B is squeezed in the middle and stretched at the sides, so the same features are at other columns. Each misplaced dark feature is paid twice (dark against bright at its old place and bright against dark at the new one). A flat mid-grey sky row (brightness about 122) is a cheaper compromise than the true, shifted row.
  • DTW finds row 63 with a clear margin (score 4,753; the next, row 62, has 12,510); the neighbouring rows 60–62 and 69 follow, as expected for nearby scanlines.
  • Brightness feature: the step from the dark pyramid base to the bright sand (above 150) is at column 119 in the query and at column 106 in B[63]; the first dark shadow (below 80) starts at column 19 in the query and at 30 in B[63]. The left side of B is stretched (features move right), the right side is compressed toward the middle (features move left). Pointwise compares these steps at the wrong columns; DTW aligns them (see the alignment in T5).
Task T5: How wide a band is enough?

Method

  • Same A, B, query and DTW as in T4; the band only restricts the cells of the table: cell (i, j) is evaluated only if |i − j| ≤ w, all other cells stay ∞. All 100 rows are still searched.
  • Widths 0, 4, 12 and unrestricted as required, plus a scan of every w from 0 to 40 to find the narrowest band that works. "Cells" counts the evaluated interior cells over all 100 rows (unrestricted: 150 × 150 × 100 = 2,250,000).
  • Check: with w = 0 only the diagonal is left, and the scores equal the T4 pointwise scores exactly (asserted in the script).
  • Prediction (before running): the squeeze moves the 25% mark to 40% and the 70% mark to 58% of the width, i.e. features move by up to about 18–23 columns. I expected w = 12 to be enough to find row 63.
  • For the unrestricted query / row 63 pair, the traceback goes from the last cell back to (0, 0) through the cheapest predecessor; the notebook's show_alignment checks the endpoints, the steps and the cost.

Discussion

  • The prediction holds, with room to spare: w = 12 finds row 63. The narrowest band that works is w = 6 (row 63 wins for every w ≥ 6); it evaluates 190,800 cells, 8.5% of the unrestricted work, a saving of 92%. For w = 1–5 the neighbouring row 64 wins; w = 0 is the pointwise failure.
  • Finding the row is easier than finding the optimal alignment: at w = 12 the cost of row 63 is still 20,999, four times the unrestricted 4,753, but the band hurts the other rows as well. The cost reaches the unrestricted value only from w = 22 on, because the optimal path deviates from the diagonal by at most 22 columns. This matches the predicted shift of the 25% mark (column 37 → 60).
  • The path shows the squeeze: it is flat at the start (query 0–37 → candidate 0–59: the stretched left side, several candidate samples per query sample), steep in the middle (query 37–104 → candidate 59–87: the squeezed part, about 2.4 query samples per candidate sample) and flat again on the right. These are the knots 25%/70% → 40%/58% of the transformation.
  • Displaced feature: the first dark shadow starts at column 19 in the query and at 30 in B[63], and the path matches them (cell (19, 30)); likewise the step to the bright sand, query 118 ↔ candidate 105. After the alignment the two signals almost coincide; the remaining cost comes mostly from the narrow dark spikes in the squeezed middle, which were partly lost when B was resampled.
