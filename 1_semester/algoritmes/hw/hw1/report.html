T1. Asymptotic winner versus practical winner
$$T_A(n) = 0.3 * n * log_2(n)\text{ milliseconds}$$ $$T_B(n) = 5 * n \text{ milliseconds}$$

Some calculations:

$$0.3 \cdot n \cdot \log_2(n) = 5 \cdot n$$ $$0.3 \cdot \log_2(n) = 5\text{ (divide both part for n)}$$ $$\log_2(n) = \frac{5}{0.3} = \frac{50}{3}\ = 16\frac{2}{3}\text{ (divide both part for 0.3)}$$ $$n = 2^{16\frac{2}{3}} = 2^{16} \cdot \sqrt[3]{2^2} = 65\,536 \cdot \sqrt[3]{4} \approx \mathbf{104\,031.92} \text{ (found Intersection point)}$$

The answers:

  • Asymptotically better T_B because after point 104_031.92 it will increase slower
  • Winner change after crossover point (n = 104_031, if we are talking about integers)
  • For 100_000 i would choose T_A (because it less than 104_031) and for 10_000_000 i would choose T_B
  • Crossover point pretty sensitive because this functions have power dependency. Besides main equality where $n = 2^{\frac{5}{0.3}}$ and ratio of constants is $\frac{5}{0.3}$ we can see 4 cases
    1. $n = 2^{\frac{6}{0.3}} = 2^{20} =1\,048\,576$
    2. $n = 2^{\frac{4}{0.3}} = 2^{13\frac{1}{3}} \approx 10\,321,3$

    4. $n = 2^{\frac{5}{0.24}} = 2^{\approx20.8} \approx 1\,825\,676,9$
T2. Empirical Validation and Operation Counting

Basic operations:

  • Linear scan: subtraction of neighboring items array[i+1] - array[i] (runs once per step).
  • Naive inversion counter: comparison array[i] > array[j] (runs every time in inner loop).
  • Library sort: comparison of elements a < b.

Operation counts and formulas:

$$C_{\text{scan}}(n) = n - 1\text{ (loop runs from 0 to n - 2)}$$ $$C_{\text{inv}}(n) = \sum_{i=0}^{n-1} (n - 1 - i) = \frac{n(n - 1)}{2} = \frac{n^2 - n}{2}\text{ (sum of arithmetic progression)}$$

For library sort we cannot write exact formula because Rust uses pdqsort. It is adaptive, so number of comparisons changes depending on how elements already ordered, chosen pivots and internal optimizations. We only know it is $\Theta(n \log n)$.

Predictions before test:

The answers:

  • Linear scan: growing strictly linear. On big sizes ($100\,000$ and $1\,000\,000$) ratio is almost exact 10 ($8.97$ and $10.05$).
  • Library sort: fits into $\Theta(n \log n)$. Ratios are between $10.65$ and $14.42$, which matches theoretical growth $\approx 10 \cdot \frac{\log_2(10n)}{\log_2(n)}$.
  • Naive inversions: clearly shows $\Theta(n^2)$. Every time size doubles, time grows $\approx \mathbf{4.1}\times$, which is very close to $2^2 = 4$. If we tried to run it for $1\,000\,000$, it would take around 50 minutes.
  • Correctness: all tests passed, manual test on [4, 1, 3, 2] gave exactly 4 inversions.
