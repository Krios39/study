Task T1: Make DFS take the long way round

Three different graphs that satisfy the task: connected, undirected, unweighted, at most eight vertices, no self-loops or duplicate edges, distinct letter labels. In each one alphabetical DFS first reaches t along a path of at least five edges, while the shortest path has exactly two edges. Pick a variant in the tabs below.

Note: here even reverse-alphabetical DFS does not find a shortest path. From A it goes to E, but at E it tries H before F and reaches F only after 4 edges. Changing the neighbour order did not "fix" DFS, it only picked a different detour.

5. What Neighbour Order Can and Cannot Change

What changes: neighbour order decides which unvisited vertex is explored next, so it changes the discovery order, the parent pointers and therefore the path that gets reconstructed. For DFS the effect is dramatic: in all three variants alphabetical DFS commits to one branch and reaches t after 5 or 6 edges. With reverse order it found a 2-edge path in variants 1 and 2, but a 4-edge path in variant 3. DFS gives no guarantee about path length, it returns whichever path its first deep dive hits. For BFS, order only changes the tie-breaking between paths of equal length (for example B-A-G vs B-C-G in variant 2, A-B-F vs A-E-F in variant 3).

What does not change: the shortest-path distance is a property of the graph itself (the minimum number of edges over all s-t paths), not of the algorithm that explores it. Reordering neighbours does not add or remove any edge, so the set of possible paths, and the minimum of their lengths, stays the same. That is why BFS, which explores layer by layer (all vertices at distance 1, then distance 2, ...), finds a 2-edge path in both orders in every variant.

4. The Shared-Pattern Idea

Comparing every pair of words would need about 4448² / 2 ≈ 9.9 million comparisons. The helper avoids that: it replaces each position of a word by * in turn, so sport produces 5 patterns *port, s*ort, sp*rt, spo*t, spor*, and puts the word into the bucket of each pattern. Two words share a bucket exactly when they agree everywhere except the starred position, that is, when they differ in exactly one letter. For example the bucket sp*rt holds sport, spirt and spurt, and all three are pairwise neighbours. So the edges are all pairs inside each bucket: the work is 5 · 4448 bucket insertions plus the (small) number of pairs inside buckets, instead of millions of comparisons. Two different words cannot share two buckets (that would mean they agree on all five positions), so no edge is produced twice.

Building the graph and searching it are two separate stages. The helper's word_graph builds all edges with pattern buckets, no search is involved. 7. Why BFS Finds a Fewest-Edge Ladder

        

            BFS processes words in the order they were discovered (FIFO queue), so it finishes all words at distance k before it discovers any word at distance k + 1.
            By induction, every word is discovered for the first time from a parent one layer closer to the start, so its parent chain has exactly as many edges as its distance.
            The first time the target is discovered, it is in the lowest layer that contains it, and the parent chain gives a ladder with the minimum number of changes.
            In the explorer above this is visible directly: spice first appears in layer 3, so no 1- or 2-step ladder exists.
        

        

            Note on depth: the BFS tree from sport over its whole component has depth 27 (from shore: 26).
            This is the eccentricity of the source within the component, not the component's diameter.

6. Discovered vs Settled

        

            Discovered means the vertex has received some finite tentative distance: the cost of the best path found so far, using only edges from vertices that are already settled.
            It is an upper bound, not the answer. Settled means the vertex was popped from the priority queue with the smallest tentative distance.
            At that moment its distance is final: every other route to it would have to leave the settled set through some vertex whose distance is already at least as large,
            and since all edge costs are positive, continuing from there can only add cost.
        

        

            Why a discovered vertex must still accept improvements: when C was discovered, only S was settled, so the only known route was the direct edge of cost 5.
            The cheaper route through A and B was simply not explored yet. If C refused the update, it would keep the wrong distance 5 and the wrong parent S,
            and every vertex reached through it (here T, 5 + 1 = 6 instead of 4) would inherit the error.
        

        

            Why stopping at discovery fails: discovery happens along the first edge that reaches a vertex, and the first edge is often an expensive one.
            Here T is discovered right away through S-T with cost 10, while the cheap chain still has three vertices waiting in the queue.
            Only when T is popped are all vertices with smaller distance already settled, so only then can no cheaper path appear.
