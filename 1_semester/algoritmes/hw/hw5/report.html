Distinguishing words from prefixes: The word-ending bit acts as a boolean flag. A node like ab serves as a routing prefix for aba and abb, but it is also a valid dictionary word itself. Setting its word-ending bit to 1 explicitly tells the algorithm that a valid word terminates at this exact node.

2. LCP Rule and Full Node Count

Full node count (N): 192,242

Why the previous word is enough for the LCP count: Because the dictionary is strictly lexicographically (alphabetically) sorted, adjacent words are guaranteed to share the maximum possible common prefix. Any word appearing before the immediate previous word will share the exact same or a shorter common prefix. Thus, comparing only with the immediately preceding word is sufficient to find the exact point where a new branch must be created.

2. Performance Analysis

Compare hashes at the same load (Weak vs Affine):

At the same load (e.g., 50%), the weak hash requires thousands of probes (1996.94), while the affine hash takes only ~1.5 probes. This happens because the maximum possible hash value for a 6-letter word using the weak function is extremely small (e.g., "zzzzzz" = 6 * 26 = 156). Therefore, 100% of the inserted words initially hash to the tiny range of slots 0–156, causing massive primary clustering. The affine hash, however, distributes the words pseudorandomly across all 8192 slots.

Compare loads for the same hash (4096 vs 7373):

For the affine hash, increasing the load from 50% to 90% significantly increases the mean absent probes from 2.44 to 56.48. As the table fills up, EMPTY slots become rare. When a collision occurs, linear probing forces the algorithm to step through increasingly long sequences of occupied slots before finding an empty one.

3. Primary Clustering & Absent vs Present Costs

Long runs of occupied slots (Primary Clustering):

In linear probing, when collisions occur, elements are placed in the next adjacent available slot. This forms a contiguous block (a "run") of occupied slots. Any new element whose hash maps anywhere within this block must step through the entire block to find an empty slot, adding to the end of the block and making it even longer. This snowball effect destroys O(1) performance.

Why absent queries cost more than successful ones:

A successful search (present) stops as soon as it finds the target word. On average, this takes traversing about half the length of the cluster. An unsuccessful search (absent) cannot stop until it encounters an EMPTY slot. Therefore, it must traverse the entire length of the cluster, explaining why absent probes are roughly double the present probes at 50% load, and scale even worse at 90% load.

3. Array Payload Sizes

  • Exact Counters (32-bit integer array): 1024 items × 4 bytes = 4,096 bytes (4 KB).
  • Morris States / Saturating (Bytearray): 1024 items × 1 byte = 1,024 bytes (1 KB).

4. The Memory, Accuracy, and Speed Trade-off

Memory vs. Speed: A smaller counter is not necessarily faster. Exact counting uses 4 KB of memory and operates at extremely high throughput (53.44 M events/s) because it only involves a simple CPU integer increment instruction (+= 1). The Morris counter saves 3 KB of memory (reducing the footprint by 4x), but its throughput collapses entirely to 1.19 M events/s. This massive slowdown occurs because updating a single Morris state requires branching (if C[v] < 255), random number generation, and expensive floating-point exponentiation for every single event in the stream.

Accuracy (Unbiased vs Exact): The saturating byte gives 100% exact answers for rare items (frequencies ≤ 255) but completely flatlines for popular items, resulting in a horrific MARE of 0.8606. The Morris counter sacrifices exactness (it relies on probabilities and introduces variance), meaning it is almost never "exact" in a single run. However, because it is an unbiased estimator, it correctly approximates the overall magnitude of heavily frequent items up to millions, maintaining a vastly superior MARE of around 0.17 compared to the naive saturating byte.
